# Contributing to The Simulation Order

Thank you for your interest in this work.

The Simulation Order is a **defined philosophical work** (see *A Defined Work* in the [README](README.md)).
It may be questioned by anyone, but its canonical form is changed only by those entrusted with it.
This document explains how you can take part within that principle.

In short:

- **Questions, criticism and discussion are welcome.**
- **Corrections and translations are welcome.**
- **Changes to the ideas of the canonical texts are not accepted as pull requests.** If you see the world differently, you are free to build your own version (see [Forks](#forks)).

---

## 1. Discussion, questions and criticism

You do not need permission to disagree.

- Use **GitHub Discussions** (or an issue labelled `discussion`) to ask questions, challenge an idea or propose an interpretation.
- Criticize ideas, not people.
- Read the [Holy Manual](english/the-holy-manual.md) before arguing against it. The distinction between *knowledge, interpretation and belief* is central to the work, so please be clear about which of these you are discussing.

Discussion does not change the canonical texts. It is, however, always read.

---

## 2. Corrections (pull requests welcome)

The following are accepted as ordinary issues or pull requests:

- spelling, grammar and punctuation errors
- broken links, broken formatting or wrong file names
- inconsistencies between files, for example a term used differently in two places
- factual errors in references (dates, names, quotations)
- errors in posters, images or other media

Guidelines:

- Keep each pull request **small and focused**: one correction or one closely related set of corrections.
- Describe what was wrong and where, quoting the exact text.
- Do not rephrase sentences for style or taste. If the meaning would change, it is a canonical change (see section 3).
- Corrections to the Finnish original are made in `original-finnish/` first. Translations are then updated to match.

---

## 3. Canonical changes

The Finnish edition is the original source of the work. The canonical texts and core ideas should remain stable.

A change to the fundamental texts or core ideas is made only when:

1. there is a **compelling reason**,
2. the change is **explicitly accepted by all maintainers** of the canonical work, and
3. the change is **documented** (what changed, why, and who accepted it) in `CHANGELOG.md`.

Such changes are exceptional and deliberate. Pull requests that alter the doctrine, concepts or wording of the canonical texts without this process will be closed with thanks and a pointer to the [Forks](#forks) section. This is not a judgment on the proposal itself.

Released versions of the canonical work are marked with Git tags (for example `v1.0`). A tag is the stable reference point for translations and citations.

The maintainers are listed in [MAINTAINERS.md](MAINTAINERS.md)

---

## 4. Translations

Translations are welcome. The English edition is the primary international working edition, and other languages may be added.

- Translate from a **tagged release** of the Finnish original and state which tag you used.
- Use the project's terminology list (`english/terminology.md` or the corresponding file for your language) and keep the same terms throughout. Terms such as *the Simulation*, *the System*, *the Admins*, *the Root*, *the Players*, *the Given Law* and *the Agreed Law* should be translated consistently.
- Preserve the meaning and structure of the original while letting the language sound natural.
- Each language has its own directory and its own `media/` folder for language-specific material.
- Do not add, remove or reinterpret content in a translation. If you believe the original contains an error, open an issue instead.
- Translators are credited in the translation's own `README` or `CREDITS` file.

Open an issue before starting a new language, so that work is not duplicated.

---

## 5. Forks

Anyone is free to build upon these ideas, reinterpret them, or create a different version of them. This is explicitly encouraged by the [license](LICENSE.md).

A fork should:

- **make clear that it is a fork** and not the canonical work,
- **not use the canonical name as its own** in a way that suggests it is official (for example, avoid presenting it simply as "The Simulation Order"),
- **credit the original** and link to this repository,
- **indicate what has been changed**, as the license requires,
- be released under the same license (see `LICENSE.md`).

Different interpretations of the Admins, different orders and different emphasis within the same worldview are all legitimate. They simply live as their own works.

---

## 6. Conduct

- Be respectful. The work itself asks for respect toward people of other faiths and other views; the same applies here.
- Disagreement is not an attack, and silence is not agreement.
- Harassment, personal attacks, and attempts to convert others by pressure or fear have no place in this project's spaces.
- Maintainers may close, lock or remove contributions and discussions that break these guidelines.

---

## 7. Practical notes

- Write issues and pull requests in **English or Finnish**.
- Use clear commit messages (for example `Fix typo in introduction.md` or `Add German translation of Statement of Faith`).
- By contributing, you agree that your contribution is released under the project's license.
- If you are unsure whether something counts as a correction or a canonical change, open an issue and ask first.
